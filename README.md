# 资金账本 · my-assets

独立于 `my-ledger` 的本地资产统计 PWA，支持日元、人民币、负债与每日总资产历史。

## 使用方式

- 顶部大按钮切换日元 / 人民币：同时切换新建资产默认币种和总资产的折算币种，不会更改已有资产的原币。
- 点击右下角猫咪「记一笔」，自己填写来源和**当前余额**，不是本次增减额。负数表示负债；日元和人民币均只允许输入整数。
- 同一币种不能有重复来源；点击已有来源更新余额。同一来源可以分别持有日元和人民币。
- 资产页负债余额显示红色，正余额和零余额使用默认文字颜色（深色模式下为白色）；「较某日」的增减额仍按增加绿色、减少红色着色。历史快照明细全部保持默认颜色，图表下的「较昨日变化」金额及百分比使用绿涨红跌。增减金额统一使用 `+ 12,345 JPY`、`- 123 CNY` 格式，金额未变时显示 `0 JPY`／`0 CNY`。资产页与该资产更新日期之前最近一次快照比较，历史每日金额与该日期之前最近一次快照比较；同币种、同一资产才比较。每天仅保存最后一次快照，不记录同日内逐笔增减。
- 资产增减比较优先匹配同一 UUID；旧快照找不到该 UUID 时，按同币种、同名来源匹配（忽略首尾空格、大小写和全半角差异）。仅有一个匹配项时才比较，兼容重新创建后 UUID 改变的来源；不会修改快照金额或 UUID。
- 编辑或删除资产时，自动按设备本地日期保存今日快照。同一天仅保留最后一次结果，之前日期不变。
- 资产日历连续展示从第一条快照到今天的全部日期，明细按日期倒序排列，不再按月筛选。图表与最高／最低金额均统计完整历史，跨月或跨年不会重置图表涨跌幅起点。
- 历史页在同一张图中叠加总资产（按所选币种折算）和实际日元／人民币资产（仅该币种原币余额）的涨跌幅。两条线分别以所显示区间首日余额为 0%，共用百分比刻度，例如 100→103 为 +3%、50→51 为 +2%，前者起伏更大。金额统计分开显示各自最高、最低和较昨日变化。图表涨跌幅按「（当日余额－首日余额）÷首日余额绝对值」计算，负债减少显示为正；首日余额为零或缺少汇率时，该线不绘制涨跌幅并提示原因，仍保留可用金额统计。中间缺少汇率时折算曲线断开，不影响实际余额。没有更新的日期沿用上次快照，包括当时的汇率，不因之后汇率变化而重算。首次记录前不补数据。
- 「较昨日变化」比较今天与昨天的金额，百分比按「（今日余额－昨日余额）÷昨日余额绝对值」计算，总资产与原币资产分别统计。昨天没有独立快照时使用昨天沿用的余额和汇率；只有今天一天记录时显示「暂无昨日记录」。今日或昨日缺少折算金额时显示「待汇率」；昨日余额为零时仍显示变化金额，注明「昨日余额为 0」，不计算百分比。
- 展开历史日期，点击对应来源的「修改历史金额」即可修正该快照余额，来源和币种不可更改。保存时按原快照汇率重新计算总资产；沿用该快照的日期同步更新，后续已保存的快照保持不变。修改最近一次快照时，当前资产余额也会同步修正，编辑窗口会提示影响范围。沿用日期的按钮会标明实际修改的快照日期。历史页不提供「更新为今日余额」，日常更新当前余额请到「资产」页操作。
- 历史中的变动百分比（较昨日变化及图表数据点提示）统一保留两位小数，例如 `+1.02%`、`-2.00%`、`0.00%`；曲线计算仍使用原始精度。
- 历史快照汇率分四行展示：标题、`1 CNY = … JPY`、`10000 JPY = … CNY`、报价日期与来源。两项换算金额均固定保留两位小数，使用快照保存的原始汇率计算。
- 首页集中显示资产汇总和汇率；人民币资产金额在首页、资产明细、历史、图表和编辑框中均四舍五入显示整数，首页「10000 日元 = … 人民币」汇率参考单独保留两位小数。旧余额编辑后按显示的整数保存；原历史快照和备份保持兼容，底层仍以分保存。

## 汇率说明

来自 [Frankfurter](https://frankfurter.dev/) 的 `CNY/JPY` 最新参考价，**不是秒级实时交易行情**。打开应用、返回前台、恢复网络以及前台每 15 分钟尝试获取，页面显示报价日期和获取时间。

当前总资产使用最新可用汇率；历史使用保存时的汇率。点击首页「刷新」时，在已有资产历史的情况下同步保存当天快照；当天没有快照则新增，当天已有则替换，过去日期不改。当天快照保存成功后才应用新汇率；联网或保存失败会提示，保留原汇率。全新空账本刷新不会创建零资产历史。

自动获取汇率及设置中的手动汇率仍只更新当前报价，不自动写入历史；需要同步当天历史时点击首页「刷新」。断网时使用缓存，设置中可以临时手动填写；下一次联网成功会恢复自动报价。无汇率时允许登记原币余额，跨币种合计显示「待汇率」，不会伪造汇率或回填过去日期的快照。

若最新接口返回晚于设备日期的报价，自动改为向同一接口查询设备当天的汇率一次，仍校验返回日期，不擅自修改报价日期。更新失败时显示具体原因（超时、HTTP 状态、网络连接或报价数据异常），保留原有缓存和历史记录。

## 本地数据与隔离

IndexedDB 数据库名 `my-assets-db`；偏好、汇率缓存和跨窗口通信均使用 `my-assets-` 前缀。PWA 路径与 Service Worker 作用域为 `/my-assets/`，不会主动读取或修改原收支账本。

两个项目是不同应用，但 GitHub Pages 同一域名下仍属于同一浏览器源：清除该域名的网站数据可能同时清除两者，浏览器也可能共享存储配额。数据不会上传到 GitHub，也不跨设备同步。不同浏览器、桌面安装实例的存储隔离取决于系统行为，不能当作备份。

请定期在设置中导出 JSON 备份。恢复会覆盖本应用全部资产与历史；不支持导入原收支账本的备份。查汇率仅发送币种，不发送资产来源与金额。

导出文件名固定为 `我的资金-完整备份.json`，是否覆盖旧文件由系统保存窗口处理。备份内容仍标识为 `my-assets`。

## 开发与部署

Node.js 22.18+（推荐最新 Node 22 LTS）。

```sh
npm ci
npm run dev
npm run build
```

开发地址包含 `/my-assets/`。发布流程执行 `npm ci` 和 `npm run build`，通过 TypeScript 编译和生产打包检查后部署，不自动运行测试。

GitHub 仓库的 Settings → Pages → Source 选择 GitHub Actions。推送 `main` 运行 `.github/workflows/deploy.yml`。默认部署路径为 `/my-assets/`，自定义时设置 `VITE_BASE_PATH`（必须包含起止 `/`）。不需要后端或 API 密钥。

版本：1.8.1。添加到主屏幕时默认名称固定为「资金账本」，不包含版本号；页面顶部「资金账本」旁显示版本号，读取 `package.json`，设置底部不再显示应用及币种说明。界面沿用原账本的奶油色和猫咪图片，素材说明见 `design/assets.md`。

点击右上角「查看更新」可手动检查更新，检查时显示「检查中…」；新版文件就绪后显示「更新应用」提示，没有新版则提示当前已是最新版本，联网失败或检查超过 30 秒会提示重试。出现「新版本已就绪」时，点击「更新应用」会显示更新进度，确认新版本激活后刷新页面；15 秒仍未完成会提示重试。返回前台或恢复网络时也会检查更新。检查不会自动刷新页面。更新只替换应用文件，不清除资产与历史数据；保存期间暂不可更新，编辑窗口关闭后再显示更新提示。
